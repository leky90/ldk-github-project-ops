# Human comment policy

Comments are handoff records, not agent telemetry.

- Post at most one comment per completed role phase.
- Store full briefs, PRDs, plans, reports, and content in durable resources.
- Never publish tokens, run IDs, leases, lock expiry, local paths, worktree baseline
  JSON, raw validator output, or hidden coordination state.
- State observed facts and mark assumptions or missing evidence.
- Update item fields only after resources and the human comment are ready.

## Handoff

1. `Handoff · From role → To role`
2. Result
3. Deliverables
4. DoD checklist
5. Evidence links
6. Limitations
7. Next action and state

## Review

1. `Review passed` or `Changes requested`
2. Reviewer role
3. Checks performed
4. Findings with severity and reproduction when relevant
5. Evidence
6. Next owner and state

## Blocked

1. Blocker
2. Impact
3. Needed from role/person
4. Resume condition

Project health belongs in a native Project status update, not an Issue comment.
